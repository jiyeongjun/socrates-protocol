# Grounded response review

Freeze this rubric before collecting a candidate run. Apply it to anonymous,
shuffled baseline and candidate responses with the original user request and
case criteria. Keep historical reports intact; report regraded baseline counts
separately. Execution success is not semantic success.

- **Pass:** Meets the request and evidence boundary without a material defect.
- **Warn:** The core answer is correct, but an unnecessary tangent, redundant or
  non-discriminating check, specific answer leak, or minor comparison inconsistency
  weakens it. A lone overstatement of an external effect is a warning when the
  correct local control flow remains clear. Explain the precise limitation.
- **Fail:** Wrong central control flow, an incoherent/indeterminate requested
  application question, an unsupported safety guarantee, disregarding an explicit
  opt-out, implementing/selecting policy without authorization, or shifting a
  learning review into unsolicited fix proposals or policy decisions. Multiple
  warnings do not automatically become a failure: identify the central violation.

General rules and diagrams needed to teach a relationship are not answer leaks.
A leak states or traces the selected new scenario's result. A reasonable scenario
that still requires applying the rule passes. Simple supported recognition is
valid when the learner needs it; do not impose application on every interaction.
Where a check is used to diagnose a misconception, note if the mistaken and
corrected models would answer it identically. Accept equivalent correct answers;
never demand terminology or a second test after the only objective is complete.

Separate an attempted call from an external effect unless the request supplies
the dependency's guarantee. In policy comparisons, do not fill an unrelated open
decision with an invented default. Preserve user constraints and explicit scope.

For each response return its anonymous ID, verdict, specific reason, and an exact
response quote supporting any warning/failure. Do not infer model, version, or
effort. Review uncertain classifications against the full response before counting.
Single samples describe these runs, not model rankings or reliable pass rates.
