## What changed

- Put evidence limits in the main skill and apply them to diagram labels. Trace return/throw boundaries before absolute statements; distinguish a call from its external effect.
- Prepare one coherent application scenario before explaining it. General rules remain teachable; a new check should distinguish the misconception and leave its own outcome unanswered.
- Keep learning review separate from unsolicited fixes and product-policy choices. Leave independent policy decisions open inside tables as well as prose.
- Preserve correct-answer completion, explicit question opt-out, existing approval, and the implementation agreement gate.

## Method and checks

- The [frozen rubric](../semantic-review.md) was written before candidate collection. Original six [scenario prompts](../grounded-learning-cases.json) were unchanged; expected criteria were withheld from tested models.
- GPT-6 Luna/Sol/Astra and Claude 5.5 Haiku/Sonnet/Opus, each low/high: 12 configurations × 6 scenarios. One candidate collection; no semantic retries until a pass.
- Claude used the run-claude workflow with explicit IDs/efforts, fresh CLI sessions per case, full inline skill/references, no tools, normal account authentication. All 36 execution checks passed, returned model IDs matched, and no permission denials occurred.
- GPT used the same desktop route as baseline: a fresh configured agent per model/effort, six vignettes in one context, explicit local skill/reference reads. Requested identity is recorded; resolved telemetry is unavailable. Codex CLI was not substituted with another model. Host and context differences prevent model rankings.
- A separate Claude Opus 5.5 high reviewer received 144 shuffled, anonymous responses in six batches of 24, without version/model labels. The primary agent checked the findings and corrected four rubric inconsistencies; both grades are preserved. Judge variability remains possible.
- Two additional [holdout prompts](../evidence-transfer-holdouts.json) tested a different sentinel loop and an explicitly idempotent remote service. Claude Sonnet 5.5 high and GPT-6 Sol high passed all four responses on primary-agent review. The remote case correctly gave two calls but one financial charge; it did not invent uncertainty about the stated contract.
- Native Claude Sonnet 5.5 high ran the writable batch-invitation workflow across four resumed turns: no file changes on three pre-approval turns, then implementation after confirmation. Hidden assertions passed for sequential ordering, partial failure, duplicate-after-failure, per-call reset, exact matching, empty input, and legacy behavior. An already-approved narrow edit and a no-question learning request also passed. This supplements vignette tests; it does not establish learner retention.
- Repository tests: 63 passed. Static catalog: 23 cases / 45 checks. Both generated skills passed parity and skill-creator validation; 13 release assets were verified. The static check was updated for the clarified same-objective question wording.

Raw host logs, session IDs and local paths remain private in ignored evaluation artifacts. Published evidence contains responses and bounded claims, not credentials or account identifiers. A GPT output-serialization quoting error created four empty files; those confirmed artifacts were cleaned and JSON validated without substituting a different response run.
