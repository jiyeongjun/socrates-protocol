# Socrates 2.0.0 구현·검증 보고서

2026-09-09에 요구사항 정렬 흐름을 구현하고 Codex Astra와 Claude Fable 5.1에서 실제 응답과 도구 호출을 검토했다. 두 호스트의 전체 시나리오 실행 후 발견한 두 가지 표현 문제를 보완하고, 영향을 받는 사례를 양쪽에서 다시 실행했다.

## 구현 결과

- 학습과 구현 정렬을 분리했다. 구현 요청에서는 LLM의 해석을 사용자가 검토하며, 사용자에게 개념 퀴즈를 내지 않는다.
- 기존 코드에서 알 수 있는 사실은 먼저 조사하고, 결과를 바꾸는 미결정 사항을 질문한다. 내부 구현 선택은 합의 범위와 저장소 관례를 따른다.
- 목표·범위·동작·관련 예외·보존할 동작·완료 조건을 확인하고, 관계에 맞는 다이어그램으로 설계를 교차 확인한다.
- 정렬 중에는 구체적 범위의 최종 확인 전 제품 코드·테스트·의존성·설정을 변경하지 않는다. 확인 후 구현과 검증을 이어가며, 동일한 범위에 받은 승인은 재사용한다.
- 사용자의 명시적 위임·확인 생략·취소를 존중하고, 침묵이나 급하다는 말로 위임을 추정하지 않는다.
- 하나의 원본에서 Codex와 Claude 패키지를 생성하며, 모델 ID는 평가 설정에만 둔다.

배치 기능의 독립 검증은 모델에게 미리 제공하지 않은 코드로 실행했다. 입력 순서, 순차 실행, 부분 실패 후 계속 처리, 실패한 첫 시도 이후 중복, 호출마다 중복 상태 초기화, 문자열 대소문자·공백 구분, 빈 입력, 기존 `invite`의 성공·실패와 `sent` 기록을 검사했다. 단일 수정은 반환 값 변경과 기존 부작용·오류 전파 보존을 검사했다.

## 발견한 문제와 보완

1. Fable의 첫 모순 사례는 순차 실행의 효과를 설명하면서 실패 시 중단까지 함께 전제했다. 선택에서 필연적으로 따라오는 결과와 별도 정책을 구분하도록 구현 정렬 지침을 보완했다. 재실행에서는 두 모델 모두 충돌 해소를 질문하고, Fable은 실패 처리도 별도로 확인할 사항이라고 명시했다.
2. Fable의 첫 학습 질문은 TTL과 원본 변경 후 경과 시간만 주어 캐시 생성 시점이 모호했다. 예측 질문 전에 초기 조건과 시간축이 답을 결정하는지 확인하도록 학습 지침을 보완했다. 재실행에서는 Astra가 갱신·만료·재확인을 명시적으로 제외했고, Fable이 캐시 생성·원본 변경 시점과 TTL을 명시했다.

보완 후 전체 시나리오를 반복하지 않고 변경의 영향을 받는 두 사례를 두 모델에서 재실행했다. 그 외 결과는 보완 전 전체 실행의 증거다. 검토는 구현을 담당한 Codex 에이전트가 수행했으며 별도의 독립 평가자 점수는 아니다.

- 생성 결과 일치 검사와 13개 릴리스 파일 검증 통과.
- 두 플랫폼의 Skill Creator 검증과 `git diff --check` 통과.
- Codex·Claude 사용자 범위에 설치한 파일 각각 6개·5개가 저장소 생성물과 바이트 단위로 일치.
- 현재 기능에서 참조하지 않는 완료된 옛 계약 문서 8개를 삭제했다.
- 빈 Claude 전용 부록과 불필요한 읽기·분기 코드를 제거했다.
- 오래된 장문 응답 예시를 축약하고, 문서의 특정 문장을 고정하던 검사 일부를 실제 링크·실행 명령 검증으로 바꿨다.
- 테스트용 임시 저장소는 삭제했다. 성공한 실제 실행의 원문 증거는 로컬의 무시되는 `.socrates-eval-results/`에 보존하고, 이번 작업에서 만든 환경 오류만 있는 보고서 4개는 제거했다.

## 재현과 증거 범위

실행 방법과 옵션은 [평가 안내](../README.md), 시나리오와 독립 검증 코드는 [실행기](../run-alignment-evals.mjs)에 있다. 최초 구버전 CLI의 모델 거절과 만료된 Claude 인증을 해결한 뒤 위 버전의 CLI로 실행했다. CLI는 테스트용 npm 캐시에서 실행했고, 저장소 의존성으로 추가하지 않았다.

실제 파일 편집이 가능한 임시 저장소에서 동일한 세션 ID를 이어 사용했다. Codex는 workspace-write, Claude는 파일 편집 도구와 허용된 Node 실행을 사용했다. 계정 인증을 유지하므로 완전히 격리된 HOME 환경은 아니다. 로컬 스킬 경로를 명시했으며, 자동 선택률이나 스킬 없는 대조군 대비 성능은 평가하지 않았다.

파일 해시뿐 아니라 응답·도구 기록을 읽어 확인 전 변경 시도가 없는지 검토했다. 다이어그램의 분기·순서·요구사항 대응을 원문으로 검토했으며, 별도 브라우저 렌더링 검사는 수행하지 않았다. 이번 행동 사례의 통과가 모든 요구사항·모든 다이어그램 유형·모든 학습 설명의 정확도를 보장하지는 않는다.
