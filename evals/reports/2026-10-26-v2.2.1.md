# Socrates v2.2.1 — 끝난 목표의 종료와 설명 범위 보존

v2.2.0에서 남았던 실패는 이미 맞게 답한 학습자에게 새 설계 과제를 붙이거나, 코드의 호출 순서를 설명하다 외부 효과의 안전성과 구현 선택을 단정하는 것이었다. **최종 후보 196개 평가 시나리오는 통과 181 / 주의 15 / 실패 0**이다. 평가 기준을 바꾸거나 실패 응답을 새 응답으로 대체하지 않았다.

## 변경

- 다른 워크플로를 읽기 전에 이번 요청에 남은 일이 있는지 판단한다. 유일한 목표의 결과와 이유를 이미 정확히 답했고 평가만 요청했다면 한두 문장으로 인정하고 끝낸다. 잘못 냈던 질문은 이 안에서 인정한다.
- 설명, 연습, 의사결정·수정 각각의 종료 지점을 초안 전에 고른다. 다음 연습·다른 목표·추가 설명·승인된 수정이 요청되었다면 해당 일을 계속한다.
- 독립 검토 도구가 없는 좁은 설명은 결론, 실행 추적, 나머지 요청 사실로 끝낸다. 외부 호출 시도와 확정되지 않은 효과를 구분하며, 명시된 외부 보장은 그대로 적용한다.
- 완성된 실행 추적에서 요청하지 않은 수정안·정책 선택·구현 선호·외부 효과 보증만 삭제한다. 답변 전체를 다시 생성하거나 대체 조언을 붙이지 않는다. 이 범위 검사는 독립 검토를 흉내 내지 않는다.
- 짧은 형식은 한 가지 국소 관계의 설명에만 적용한다. 넓은 시스템 설명, 요청된 상세 설명, 연습, 선택, 수정은 이 제한을 받지 않는다. 기존 독립 검토가 필요한 경우에는 응답을 내보내기 전에 완료한다.

## 최종 비교

숫자는 **통과 / 주의 / 실패**다. 원래 여섯 사례와 의미 판정 기준의 SHA-256 `0f56dedafea9dbfcb013cf9f869de5097b07ffd2507a908324c4c97ccd730d4a`를 유지했다.

| 실제 파일 로딩·독립 검토 허용, 각 12건 | 11 / 1 / 0 | **12 / 0 / 0** |
| 새 종료 경계 사례 8건, Haiku low | 7 / 1 / 0 | 아래 20건에 포함 |
| 기존 역방향 8 + 독자 경계 4 + 새 종료 경계 8, Haiku low | 동일 20건 묶음 비교 없음 | **15 / 5 / 0** |

| 핵심 실패 경로 3개 × 10회 | 중간 비교는 첨부 기록 참조 | **27 / 3 / 0** |

작성자 번들은 GPT-6 Luna/Sol/Astra와 Claude 5.5 Haiku/Sonnet/Opus 각각 low/high, 조합당 여섯 사례다. Claude CLI는 2.1.284이며 GPT는 명시한 모델·effort의 데스크톱 에이전트다. GPT 에이전트 하나는 여섯 독립 상황 묘사를 같은 컨텍스트에서 처리한다. 네이티브 36건은 Claude 여섯 조합이며 사례마다 새 프로세스에서 실제 스킬 파일을 읽는다. 이 결과를 서로 다른 호스트의 모델 순위로 해석하지 않는다.

독립 검토 12건은 Haiku low와 Sonnet high다. 12/12 실행이 성공했고, 필요한 검토 8/8건의 실제 완료를 확인했다. 검토 모델은 Opus 5.5이며 해당 하위 검토자의 effort는 텔레메트리로 확인할 수 없다. 도구 없는 36건과 Claude 작성자 번들 36건도 모두 실행에 성공했다. 실행 성공과 의미 판정은 별도로 보존했다.

반복 30건은 실제 로딩 Haiku low의 `minimum-equivalent`·`changed-evidence`, 작성자 번들 Haiku high의 `changed-evidence`를 각각 열 번 실행했다. 새 종료 경계 여덟 사례는 다음 연습, 다음 목표, 이유 없는 결과, 잘못 낸 질문의 종료, 승인된 수정 두 종류, 여러 요청 사실, 명시된 외부 효과를 포함한다. 기준은 응답 생성 모델에 제공하지 않았다.

Sonnet high의 실제 구현·학습 여섯 시나리오는 총 열 턴이다. 승인 전 파일 불변, 승인 후 독립 수용 검사, 명확히 승인된 수정의 직접 수행을 기계적으로 확인했다. 의미 검토에서 원자성 설명에 불필요한 내구성 설명을 붙인 한 건은 주의로 남겼다.

## 판정과 원기록

버전·모델 표시를 가리고 섞은 324행을 Opus 5.5 high가 고정 기준으로 채점했다. 기준본 128행과 후보 196행이며, 반복과 기존 기준본의 재사용이 포함된다. 324개의 새로운 독립 요청이나 성공 확률 추정치가 아니다. 기준본을 새 묶음에서 다시 채점하므로 과거 보고서와 판정 수가 다를 수 있다. 과거 보고서는 덮어쓰지 않는다.

한 채점 배치의 누락 한 건은 기존 아홉 판정을 보존하고 해당 ID만 추가 채점했다. 모든 ID의 일대일 대응과 주의·실패 인용의 실제 응답 포함 여부를 검사했다. GPT Luna high의 JSON 포장에는 이스케이프되지 않은 따옴표 세 쌍이 있었다. 원문을 보존하고 JSON 이스케이프만 고쳤으며 응답 문구는 다시 생성하지 않았다. 이를 의미적 실패와 분리한 산출물 형식 오류로 기록한다.

최종 주의 15건은 불필요한 과정·주변 설명, 외부 효과나 정책 충족의 일부 과장, 부정확한 인과 문장·도식 표기다. 각 응답·판정·인용을 첨부한다. **주의를 통과로 합산하지 않았다.** 이번 표본에서 기존 실패 경로를 막은 것이며, 모든 미래 답변의 정확성을 보증하는 수치는 아니다.

GPT-6 Astra high가 최종 묶음의 모든 비통과 34행을 별도로 검토했다. 후보의 주의 판정은 유지할 수 있다고 판단했고, 기준본 S057·S159 두 건은 주의보다 실패가 적절하다는 의견을 냈다. 표는 최초 판정을 그대로 유지하며 이 상향 의견도 별도 첨부한다. 후보에 유리하도록 기준본 점수를 바꾸지 않았다.

## 중간 후보를 보류한 이유

종료 문구만 추가한 후보, 불확실성을 국소적으로 표시한 후보, 짧은 설명 형식만 강제한 후보는 반복 시험에서 구현 제안이나 정책 단정이 재발했다. 중간 후보 C4는 15건에서 실패가 없었지만 새 반복과 전체 행렬에서 다시 실패했다. C6도 전체 행렬에서는 실패가 없었으나 새 30회 반복에서 실패 한 건이 나왔다. C7의 내부 재시도 반례, C8의 결론·추적 형식만으로도 각각 실패 한 건이 남았다.

C9는 마지막 범위 검사를 **삭제만 하는 작업**으로 제한했다. 전체 초안을 재작성하면서 새 조언이나 보증을 다시 붙이는 경로를 줄이고, 최종 소스로 행렬·역방향·반복·실제 구현 검사를 다시 수행했다. 실패했던 C1–C8의 소스·응답·판정은 최종 결과와 분리해 보존한다. 작은 탐색 표본이므로 특정 문장 하나의 인과 효과를 입증했다고 주장하지 않는다.

## 검증과 재현

저장소 단위 테스트 84개, 정적 계약 검사 45개, 생성본 일치, 릴리스 자산 15개, 양쪽 스킬 형식, 임시 전역 설치의 배포 파일 13개와 두 버전 매니페스트를 확인한다. PR 생성 직후 및 실제 전역 설치 후의 스모크 결과는 릴리스 설명과 첨부 증거에 기록한다.
