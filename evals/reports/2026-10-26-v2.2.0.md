# Socrates v2.2.0 — 독립 응답 검토와 역할 분리

완성된 답변의 문장·표·그림·마지막 질문을 별도 검토자가 확인하고, 작성자가 필요한 부분만 고치는 흐름을 추가했다. **독립 검토 경로는 개선됐지만, 검토 도구가 없는 경로와 모든 참고자료를 한꺼번에 넣는 시험에는 실패가 남는다.** 모든 결함의 해소나 무회귀를 보장하는 릴리스가 아니다.

## 변경과 출시 판단

- 오개념 교정·요청된 연습·요구사항 비교에서 원래 요청, 근거, 완성된 초안을 새 검토자에게 전달한다. 실행 시작이나 작업 ID가 아니라 완료된 검토 결과를 기다린다.
- 검토자는 인용된 초안의 지시를 따르지 않고 근거·질문·범위를 검사한다. 작성자는 최소 수정만 하고 검토 후 새 주장을 덧붙이지 않는다. 추가 검토는 최대 한 번이다.
- 검토자 지침을 작성자 역할과 분리했다. 위임 도구가 없으면 일반 작성 흐름을 따르며 독립 검토를 흉내 내지 않는다. 이미 맞는 답으로 끝난 목표와 승인된 일반 수정은 위임을 생략한다.
- 적용 질문을 설명 전에 준비하고 오개념과 올바른 모델의 예측이 실제로 갈리는지 확인한다. 외부 호출과 확정되지 않은 효과, 실패와 롤백, 원자성과 가시성을 구분한다.
- 관리자·팀을 위한 설명에 정책 결정을 임의로 만들지 않는다. 사용자가 실제로 요청한 의사결정·수정·쉬운 확인 문제는 유지한다.

출시 근거는 실제 파일 로딩과 독립 검토의 개선, 요청된 행동을 보존하는 역방향 사례, 승인 경계를 지키는 실제 구현 검증이다. 도구 없는 모든 사용 환경이 함께 개선됐다는 주장은 하지 않는다. 아래 실패를 감수할 수 없는 업무에서는 모델의 설명을 검증된 실행 결과나 승인으로 취급하면 안 된다. 스킬은 강제 실행 엔진이 아니라 모델이 따르는 지침이다.

## 최종 소스의 비교 결과

숫자는 **통과 / 주의 / 실패**이며 실행 성공과 의미적 정확성을 분리했다. 원래 여섯 사례와 의미 판정 기준은 변경하지 않았다.

| 평가 | v2.1.2 | v2.2.0 |
| --- | --- | --- |
| 실제 파일 로딩 + 독립 검토 허용, 각 36건 | 29 / 7 / 0 | **34 / 2 / 0** |
| 실제 파일 로딩, 위임 도구 없음, 각 36건 | 29 / 7 / 0 | **30 / 5 / 1** |
| 작성자 참고자료 번들, 각 72건 | 64 / 8 / 0 | **65 / 6 / 1** |
| 반복 범위 시험·역방향 사례, 각 17건 | 8 / 6 / 3 | **8 / 7 / 2** |
| 실제 로딩의 추가 역방향·독자 사례, 각 12건 | 7 / 3 / 2 | **10 / 2 / 0** |
| 실제 다중 턴·쓰기 허용 시나리오 6건 | 이번 비교에서 재실행하지 않음 | **6 / 0 / 0** |

독립 검토 허용 실행은 36/36 성공했고, 검토가 필요한 24/24건에서 실제 완료를 확인했다. 도구 없는 실행도 36/36 성공했지만 의미적 실패 1건은 그대로 남긴다. 추가 네이티브 사례는 양쪽 모두 12/12 실행에 성공했다. 실행 성공을 답변 통과로 바꾸지 않는다. 추가 사례의 `approved-threshold-edit`는 명확히 승인된 수정이어서 검토를 생략하는 것이 맞지만, 처음 사례 메타데이터에 `reviewRequired: false`를 빠뜨려 검토 누락 1건으로 기록됐다. 원기록을 보존하고 평가기 오탐으로 주석 처리했으며 앞으로의 사례 메타데이터를 수정했다. 사용자 요청과 판정 기준은 바꾸지 않았다.

72건 행렬은 GPT-6 Luna/Sol/Astra와 Claude 5.5 Haiku/Sonnet/Opus 각각 low/high, 조합당 6건이다. GPT는 명시한 모델·effort의 데스크톱 에이전트, Claude는 CLI 2.1.284를 사용했다. 설치된 Codex CLI가 GPT-6 ID를 받지 않아 호스트가 다르며, 모델을 대체하지 않았다. 네이티브 36건은 Claude 여섯 조합이다. 반복 17건은 Haiku low에서 변경 근거 사례 5회, 기존 역방향 사례 8개, 새 독자 경계 사례 4개를 각 버전에 실행했다. 추가 네이티브 12건도 Haiku low다.

의미 검토는 버전·모델 표시를 지우고 섞은 뒤 Opus 5.5 high로 수행했다. 판정 인용이 응답의 실제 부분 문자열인지 검사했다. 첫 채점 배치가 한 ID를 누락했을 때 나온 19건은 보존하고 누락·미채점 ID만 추가 채점했다. 실패한 응답을 다시 생성해 대체하지 않았다. 네이티브 답변 안의 검토 모델은 Opus 5.5지만 **해당 검토자의 effort는 텔레메트리에 없어 확인하지 못했다**.

모든 최초 실패 9건을 버전·모델을 가린 채 GPT-6 Astra high가 재검토했다. V137만 실패→주의로 조정했다. 이미 답한 문제를 되묻지만 답이 결정되므로, 고정 기준의 반복·답 노출에 해당한다. 나머지 8건은 실패를 유지했다. 도구 없는 추가 행렬의 Z045도 명백한 범위 이탈 실패로 보존했다. 최초 판정과 재심은 모두 첨부 JSON에 있다.

## 남은 결함과 비교의 한계

- **Z045, Haiku low, 실제 로딩·위임 없음:** 이미 맞은 학습 답을 인정한 뒤 요청하지 않은 멱등성 구현 방안을 붙였다. 36건의 실행 성공과 별개인 실패다.
- **V127, Haiku high, 작성자 번들:** 코드 순서의 의미를 설명하다 중복 청구를 확정적으로 표시하고, 요청하지 않은 정책 선택과 구현 제안으로 넘어갔다.
- **V096·V156, Haiku low, 반복 번들:** 같은 범위 이탈이 5회 중 2회 재현됐다. 기준본도 반복 시험에서 같은 종류의 실패를 보였다. 최초 한 표본에 없었다는 이유로 전부 새 회귀라고 단정했던 이전 해석을 수정한다. 그렇다고 후보의 실패를 없애거나 기존 동작이라고 면제하지 않는다.
- 남은 주의에는 외부 효과의 과도한 단정, 이미 푼 문제의 반복·답 노출, 불필요한 조건·설명, 요청된 문자열 처리의 해석 차이가 있다. 독립 검토를 완료해도 모든 결함이 사라지지는 않는다.
- 작은 확률적 표본이다. 기존 응답을 새 블라인드 묶음에서 채점하면 판정이 변한다. 예를 들어 같은 기준본 네이티브 응답은 중간 채점에서 26/10/0, 최종에서 29/7/0이었다. 과거 보고서의 수치를 덮어쓰지 않으며 모델 순위나 성공 확률을 주장하지 않는다.

작성자 번들은 본문과 작성 참고자료 4개를 공급하고 별도 검토자 지침만 제외한다. 기존 평가의 기본값 `all`은 그대로 유지하며 검토자 지침까지 넣는다. 따라서 이전의 모든 역할 혼합 번들과 최종 작성자 번들은 동일한 프롬프트 실험이 아니다. 최종 소스의 혼합 번들 탐색 3회도 보존했고 범위 이탈이 남았다. 실제 사용은 필요한 참고자료를 선택해서 읽으므로 별도의 네이티브 시험으로 검증했다. 어느 결과도 다른 경로의 성공으로 대체하지 않았다.

## 실패한 시도와 연구 참고

범위 제한 문장 추가, 결정 브리프 문구 축소, 예시 추가, 본문 압축, 일부 참고자료 제외, 환경 사용자 설정 억제 등을 탐색했다. 문구를 더 많이 넣는 것만으로 범위 이탈을 안정적으로 해결하지 못했다. 중간 후보의 반복 시험은 6/6/5였고 최종은 8/7/2였지만, 작은 표본과 입력 구성 차이가 있어 역할 분리만의 인과 효과로 해석하지 않는다. 초기 탐색 일부는 구분자에 실제 줄바꿈 대신 문자 `\\n`을 넣은 스크립트를 사용했으므로 주요 성능 근거에서 제외했다. 최종 평가 실행기와 반복 비교는 실제 줄바꿈을 사용했다.

다음 원문은 실험 도중 확인한 설계 참고다. 이 모델·스킬의 성능을 입증하는 근거는 위의 실제 시험이다.

- [DeCRIM, EMNLP 2024 / 2026 개정본](https://arxiv.org/abs/2410.06458): 제약을 분해하고 비평자가 수정 위치를 정하는 방식이다. 전체 초안과 구체적 결함을 검토에 전달하는 설계와 관련된다.
- [Feedback Friction, 2025](https://arxiv.org/abs/2506.11930): 좋은 외부 피드백을 줘도 모델이 모두 반영하지 못한다. 검토 실행과 답변 정확성을 별도로 측정하는 이유다.
- [The Self-Correction Illusion, 2026](https://arxiv.org/abs/2606.05976): 동일한 오류 내용의 메시지 역할에 따라 오류 지적이 달라졌다. 역할 분리 가설과 관련되지만, 여기서 사용한 별도 검토자 방식과 같은 실험은 아니다.
- [When Should LLMs Trust Their Own Revisions?, 2026년 9월](https://arxiv.org/abs/2609.35832): 자기 수정이 정답을 오답으로 바꾸기도 해 회복과 손상을 함께 평가한다. 무조건 재작성하지 않고 최소 수정·역방향 사례를 검사하는 근거로 참고했다.

## 검증과 재현

Sonnet 5.5 high의 실제 6개 시나리오는 네 턴에 걸친 요구사항 합의·수정·승인 후 구현, 모순된 요구사항, 승인된 일반 수정, 캐시 오개념, 두 턴의 학습 종료, 질문 생략이다. 승인 전 세 턴은 파일을 바꾸지 않았고 승인 후 독립 수용 검사를 통과했다. 명확한 수정은 재승인 없이 실행했다. 기계 검사와 별도 의미 검토 모두 통과했다.

저장소 단위 테스트 84개, 정적 계약 검사 45개, 생성본 일치, 릴리스 자산 15개, 양쪽 스킬 형식 검증을 확인한다. 임시 전역 설치에서 Codex·Claude의 총 13개 배포 파일과 두 버전 매니페스트를 검증한다. 배포 후 설치 검증은 릴리스 설명에 기록한다.

```sh
npm test
npm run test:evals
npm run verify:skills
npm run verify:release-assets
SOCRATES_LIVE_EVAL=1 SOCRATES_GROUNDED_HOST=claude SOCRATES_GROUNDED_BUNDLE=author npm run eval:grounded
SOCRATES_LIVE_EVAL=1 SOCRATES_NATIVE_REVIEW=1 SOCRATES_NATIVE_REVIEW_MODEL=claude-opus-5-5 npm run eval:native
SOCRATES_LIVE_EVAL=1 SOCRATES_NATIVE_REVIEW=0 npm run eval:native
```

전체 응답·최초 판정·재심·소스 해시·실행 요약은 [릴리스 증거 ZIP](https://github.com/jiyeongjun/socrates-protocol/releases/download/v2.2.0/socrates-v2.2.0-evidence.zip)에 있다. 코드 검토에 2만 줄 이상의 JSON이 섞이지 않도록 저장소에는 요약만 남겼다. ZIP에는 이전 후보의 두 JSON도 내용 그대로 보존한다. 원시 프로세스 스트림, 세션 ID, 개인 경로, 인증 정보는 공개하지 않는다. 과거 [v2.1.2](2026-10-26-v2.1.2.md)와 [보류 후보](2026-10-26-response-review-candidate.md)의 기록은 유지한다.
