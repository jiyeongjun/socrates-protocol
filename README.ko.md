Socrates는 Codex와 Claude Code에서 자연어 의도를 코드까지 일관되게 연결하는 스킬입니다. 기존 맥락을 조사하고, 결과를 바꾸는 빈칸에 질문하고, 요구사항과 설계를 교차 확인한 뒤 합의한 범위를 구현하고 검증합니다. 개념·코드·트레이드오프·장애 원인을 설명하는 **시각화 우선 학습 스킬**의 역할도 유지합니다.

## 코딩 요청을 정렬하는 흐름

```text
요청 → 코드와 맥락 조사 → 중요한 미결정 사항 확인
    → 역질문과 답변 반영 → 동작과 완료 조건 합의
    → 필요한 다이어그램 교차 확인 → 최종 확인
    → 구현 → 합의한 동작 검증
```

LLM이 자신이 이해한 요구사항을 제시하고 사용자가 수정합니다. 사용자에게 구현 개념을 퀴즈로 묻지 않습니다. 기존 코드에서 알 수 있는 사실은 직접 조사하고, 답에 따라 동작·범위·데이터 의미·실패 처리·중요한 설계 제약이 달라지는 부분을 질문합니다. 합의한 동작 안의 내부 구현은 저장소 관례를 따릅니다.

Codex에서는 `$socrates 일괄 초대 기능을 추가해줘. 코딩 전에 원하는 동작부터 맞추자`, Claude Code에서는 `/socrates`로 호출합니다. 중요한 해석 차이가 생길 수 있는 기능 요청에도 자동으로 선택될 수 있습니다. 이미 명확하고 승인된 일반 수정에는 추가 확인 절차를 붙이지 않습니다.

구현 전에는 목표·범위·실제 동작·관련 예외·유지할 기존 동작·완료 조건을 간결하게 확인합니다. 결과를 바꾸는 미결정 사항이 남아 있으면 정렬됐다고 선언하지 않습니다. 객체 책임은 클래스, 모듈 경계는 컴포넌트, 호출 순서와 실패는 시퀀스, 데이터 변환과 저장은 데이터 흐름도, 수명주기는 상태도, 조건 분기는 플로우차트로 확인합니다. 현재 동작과 제안을 구분하고 중요한 실패 경로를 포함합니다. 단순한 변경은 그림 없이 진행합니다.

정렬 흐름의 최종 확인은 구체적인 요구사항과 설계를 대상으로 합니다. 확인 전에는 자료 조사와 채팅 안의 설계를 진행하되 제품 코드·테스트·의존성·설정은 수정하지 않습니다. 동일한 구체적 범위에 대해 이미 받은 최종 승인은 재사용합니다. 사용자의 명시적인 결정 위임이나 확인 생략 지시는 존중하지만 침묵이나 급하다는 말로 이를 추정하지 않습니다. 확인 후 구현과 검증을 이어가고, 합의한 동작·범위·제약이 달라져야 할 때만 해당 결정을 다시 확인합니다.

학습에서는 사용자가 관계를 이해했는지, 구현에서는 LLM의 해석이 사용자 의도와 맞는지를 확인합니다. 학습 중 퀴즈를 생략해 달라는 말이 제품 정책의 결정 위임을 뜻하지는 않습니다. 스킬만으로 정합성을 보장할 수는 없으므로 실제 결정 과정·도구 호출·완료 조건의 검증 결과를 함께 평가합니다.

[구현 정렬 지침](reference/skill-references/implementation-alignment.md)과 [실제 모델 평가 안내](evals/README.md)를 참고하세요.

## 학습 동작

버전 2.2.1은 요청된 학습 목표가 이미 완료됐는지 먼저 판단합니다. 맞은 답으로 끝난 목표는 짧게 확인하고 마치되, 별도로 요청한 연습·설명·승인된 수정은 계속합니다. 독립 검토가 없으면 짧은 코드 설명을 결론·실행 흐름·나머지 요청된 사실로 구성하고, 요청 밖의 제안과 근거 없는 보증 문구만 삭제합니다. 답 전체를 다시 쓰지 않습니다.

버전 2.2는 오개념 교정·요청된 연습·요구사항 비교에서 완성된 초안을 검토합니다. 호스트가 에이전트 위임을 지원하면 새로운 읽기 전용 검토자에게 원래 요청, 근거, 그림·표·마지막 질문까지 전달하고 실제 검토 결과를 받은 뒤 필요한 부분만 수정합니다. 이미 맞는 답으로 목표가 끝났거나 명확한 일반 수정이면 생략합니다. 위임 도구가 없으면 일반적인 근거 중심 작성 흐름을 따르며, 검토자 전용 지침을 읽거나 검토자를 흉내 내지 않습니다. 실행 시간과 비용이 추가될 수 있고, 런타임이 강제하는 차단 장치는 아닙니다.

적용 질문은 설명 전에 준비해 오해한 모델과 올바른 모델의 답이 실제로 갈리는지 확인합니다. 외부 호출과 확정되지 않은 효과, 실패 중단과 롤백, 원자성과 동시 조회의 가시성을 구분합니다. 사용자가 요청한 수정·추가 선택지·쉬운 확인 문제는 유지합니다. 비교 실험, 검토 생략, 실패한 초기 호출, 남은 결함은 보고서에 공개합니다. 과거 [v2.1.2 결과](evals/reports/2026-10-26-v2.1.2.md)는 그대로 보존합니다.

v2.1에서는 [Sphinx](https://github.com/parthh01/sphinx)의 아이디어를 참고해 근거와 질문의 품질을 보완했습니다. 질문 전에 최소 결과·인과관계를 정하고, 사용자를 판단하기 전에 질문 자체를 검증하며, 적용 능력이 중요할 때 조건이 달라진 사례를 사용합니다. 같은 의미의 답을 인정하고 뒤늦게 합격 조건을 추가하지 않습니다. 잘못된 질문은 설명자의 오류로 수정하고, 버그를 이해하는 것과 승인하는 것을 구분합니다. 근거가 바뀌면 영향을 받은 결론만 재확인합니다. 이는 대화 규칙이며 Git 차단이나 완전한 이해의 보증이 아닙니다. 구현 정렬을 사용자 퀴즈로 바꾸지도 않습니다.

답이 어긋나면 다음 내용으로 넘어가지 않습니다. 이해하지 못한 부분만 다른 그림·비유·사례로 다시 설명하고, 사용자의 답에서 핵심 관계가 정확히 드러날 때까지 같은 목표를 이어갑니다.

## 어떻게 동작하는가

```text
요청
  ↓
큰 흐름을 시각화
  ↓
핵심 질문 하나
  ↓
사용자의 답
  ├─ 핵심 관계가 맞음 → 다음 단계 또는 종료
  └─ 틀리거나 부족함 → 해당 부분을 다시 그림 → 같은 목표 재확인
```

여기서 “얼라인됐다”는 모델이 사람의 머릿속을 100% 안다는 뜻이 아닙니다. **현재 학습 목표의 핵심 관계를 사용자가 자기 말로 정확히 설명하거나 새 사례에 적용했다**는 관찰 가능한 기준입니다.

사용자가 질문을 원하지 않거나 답을 바로 달라고 하면 문답을 멈춥니다. 다른 사람에게 보낼 설명 자료를 요청한 경우에도 완성된 자료만 제공합니다.

## 언제 쓰는가

| 원하는 결과 | 요청 예시 | Socrates의 동작 |
|---|---|---|
| 코딩 의도 정렬 | `$socrates 일괄 초대를 추가해줘. 코딩 전에 동작과 설계부터 맞추자.` | 코드 조사, 중요한 빈칸의 역질문, 설계 교차 확인을 거쳐 최종 확인 후 구현 |
| 처음 보는 개념 이해 | `$socrates 데이터베이스 인덱스를 백엔드 입문자에게 설명해줘.` | 전체 구조를 먼저 그리고 핵심 질문 하나로 이해를 확인 |
| 코드나 모듈 흐름 파악 | `$socrates 이 결제 모듈이 어떻게 동작하는지 코드 근거로 보여줘.` | 실제 코드를 읽고 데이터·제어·실패 경로를 시각화 |
| 기존 시스템에 기능 추가 | `$socrates 주문 서비스에 예약 주문을 넣기 전에 현재 흐름과 연결 지점을 설명해줘.` | 현재 동작과 제안을 구분하고 지켜야 할 규칙과 테스트까지 연결 |
| 트레이드오프 이해 | `$socrates polling과 webhook의 선택 기준을 그림으로 설명해줘.` | 장점과 비용을 같은 인과관계 위에 배치 |
| 장애 원인 이해 | `$socrates 이 타임아웃 장애가 왜 재시도 폭증으로 이어졌는지 보여줘.` | 원인·전파·영향·복구를 타임라인이나 피드백 루프로 표현 |
| 내 이해 점검 | `$socrates 내가 이해한 캐시 갱신 방식은 이래. 틀린 연결을 찾아줘: ...` | 맞는 부분과 어긋난 부분을 나누고 같은 목표를 다시 확인 |
| 다른 사람에게 전달 | `$socrates 이 장애를 매니저에게 보여줄 한 장 설명으로 만들어줘.` | 원래 사용자를 퀴즈 내지 않고 바로 공유할 수 있는 결과물 작성 |

## 일반 응답과 무엇이 다른가

Socrates가 모델을 더 똑똑하게 만드는 것은 아닙니다. 차이는 설명을 매번 같은 학습 흐름으로 이끈다는 점입니다.

| 상황 | 일반 응답 | Socrates |
|---|---|---|
| 설명 시작 | 문단·불릿·표 중 모델이 임의로 선택 | 큰 흐름을 그림으로 먼저 제시 |
| 이해 확인 | 생략하거나 여러 질문을 붙일 수 있음 | 핵심 관계를 확인하는 질문 하나만 제시 |
| 틀린 답 | 정답을 알려준 뒤 다른 주제로 갈 수 있음 | 다음 단계로 넘어가지 않고 해당 부분을 다시 시각화 |
| 코드·장애 설명 | 요약이나 해결책부터 제시할 수 있음 | 현재 흐름과 인과관계를 먼저 보여주고 근거와 제안을 구분 |
| 반복 사용 | 요청할 때마다 형식이 달라질 수 있음 | 시각화 → 질문 → 교정이라는 흐름을 유지 |

일반 모델도 명시적으로 “시각화하고 질문 하나를 해 달라”고 요청하면 좋은 답을 만들 수 있습니다. Socrates의 가치는 정확도 우위가 아니라 이 형식을 매번 다시 적지 않아도 된다는 데 있습니다.

## 어떤 시각화를 만드는가

- Codex나 Claude Code가 아티팩트·시각화 화면을 지원하면 그 기능을 우선 사용합니다.
- ELI5나 그림 설명을 요청하면 큰 다이어그램과 적은 글자로 구성된 자체 완결형 HTML 아티팩트를 우선합니다.
- 해당 기능이 없으면 채팅 안에 흐름도·타임라인·상태도·트리·비교표를 만듭니다.
- 사용자가 파일을 요청하지 않았다면 HTML을 만들기 위해 저장소에 파일을 추가하지 않습니다.
- 코드와 시스템은 먼저 원문을 읽고, 현재 동작·제안·모르는 부분을 시각적으로 구분합니다.

단순한 사실에는 장식용 그림을 붙이지 않습니다. 화살표·색·경계·라벨은 모두 실제 관계를 설명해야 합니다.

## 실제 응답 테스트

편집 가능한 임시 저장소에서 여섯 시나리오를 검증합니다. 이번 버전은 Sonnet 5.5 high로 실행했습니다. 네 턴에 걸친 구현 합의, 모순된 요구사항, 이미 승인된 수정, 학습 오개념 교정, 정답 이후 학습 종료, 질문 생략을 다룹니다. 실제 도구 호출과 파일 변경을 기록하고 구현 후 별도로 준비한 완료 조건을 검증합니다. 실행 명령·모델 선택·격리 범위·의미 검토 기준은 [평가 안내](evals/README.md)에 정리했습니다.

2026-09-09 실행에서는 두 가지 표현 문제를 보완하고 관련 사례를 재실행한 뒤 구현·회귀 검증을 통과했습니다. 근거·수정 이력·검증 범위는 [검증 보고서](evals/reports/2026-09-09.md)에 기록했습니다.

이전 v1.1.0 학습 평가는 2026-08-24에 Codex로 실행한 기록입니다. 현재 모델이나 새 구현 흐름의 검증 결과로 사용하지 않습니다.

|---|---|
| Codex | `$socrates <요청>` |

설명·학습·ELI5·그림 설명·코드 흐름·트레이드오프·장애 원인·멘탈 모델 점검 요청에도 자동으로 선택될 수 있습니다. 이미 명확한 일반 코드 수정이나 짧은 문장 편집을 학습이나 추가 승인 절차로 바꾸지 않습니다.

## 설치

Node.js 22 이상과 Codex 또는 Claude Code가 필요합니다.

현재 사용자에게 Codex와 Claude Code용 스킬을 함께 설치:

```bash
node scripts/install.mjs --mode install --platform both --scope global --source-root "$PWD"
```

### 기존 버전에서 업데이트

저장소를 최신 상태로 받은 뒤 설치 명령을 다시 실행하면 관리 중인 스킬이 v2.2.1으로 교체됩니다. 릴리스 태그를 발행하기 전에도 로컬 원본 설치 명령을 사용할 수 있습니다.

v0.10.0을 사용했다면 이전 설치를 먼저 제거합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/jiyeongjun/socrates-protocol/v0.10.0/scripts/install.mjs \
  | SOCRATES_INSTALL_RUN=1 node --input-type=module - --mode uninstall --platform both --scope global --version v0.10.0

node scripts/install.mjs --mode install --platform both --scope global --source-root "$PWD"
```

설치 스크립트는 설치 주체를 확인할 수 없거나 사용자가 수정한 기존 폴더를 강제로 지우지 않습니다.

reference/skill-body.md
reference/skill-references/
        │

        └── .claude/skills/socrates/   # Claude Code

```bash
npm run build:skills
npm run verify:skills
npm run verify:release-assets
npm run test:evals
npm test
```

평가 세트에는 설명, 시각화, 대화형 학습, 독자에 맞춘 설명, 일반 작업 비개입, 패키징을 다루는 테스트 사례 23개와 자동 판정 45개가 있습니다.

구현 정렬과 학습 회귀는 편집 가능한 별도 평가로 두 호스트에서 확인합니다. 다음 명령은 최신 CLI와 해당 계정 인증을 사용해 실제 모델을 호출합니다.

```bash
SOCRATES_LIVE_EVAL=1 SOCRATES_ALIGNMENT_HOST=codex npm run eval:alignment
SOCRATES_LIVE_EVAL=1 SOCRATES_ALIGNMENT_HOST=claude npm run eval:alignment
```
